八個小測試：右邊贏在哪，輸在哪

同一段小程式用兩種 abstract machine 來跑，兩邊都疊著做，數做完要幾個 cycle。四個測試是 interaction net 佔便宜的情況，四個是它沒辦法的情況。每個測試有 3D 動畫，也有一張把資料放大之後的比較圖。

還不清楚 abstract machine 是什麼，先看文章 How to read the Frostbite announcement 的第 4 節。每個測試先寫出題目。題目下面那段程式是一般程式語言的寫法，也就是把題目寫成 von Neumann machine 之後的樣子；右邊的圖是同一題寫成 interaction net。

八個測試合起來看

    
    
      
  • 右邊贏的四個，共同點是工作之間沒有先後關係：切得開的資料、互不相干的迴圈、可以一格一格交接的兩段處理、不需要猜的分支。
    • 
      
  • 右邊輸的四個，原因各不相同：一條相依鏈疊不起來；沒有 address，拿不到「第 k 筆」；一個值只能給一個人，共用就要複製；用不到的資料要花力氣丟。
    • 
      
  • 加 tile 只在第一類有用。在相依鏈、查表、找到就停這三個測試裡，1 個 tile 和 16 個 tile 的時間一樣。
    • 
    

  


  

    
兩邊的假設

    
    
      
  • 左邊是一顆單發射、in-order 的 core：四級 pipeline，一個 cycle 進一道 instruction；有 forwarding；JMP、CALL、RET 的目標抓得到；條件分支查一張 2-bit 的預測表，猜錯作廢兩道。
    • 
      
  • 右邊的 tile 是「一個執行單元」：可以想成專用硬體的一塊，也可以想成軟體 runtime 的一條 thread。這一頁數的是 abstract machine 本身的 cycle，沒有算進軟體 runtime 每一步多花的 instruction，所以呈現的是這個 abstract machine 在理想的執行單元上能做到的程度。Interaction net 多年來都是用軟體在一般 CPU 上執行，第一個硬體原型到 2024 至 2025 年才出現；實測比這裡的數字慢；專用硬體能做到多接近，還沒有量測。
    • 
      
  • 右邊每個 tile 每個 cycle 可以開始一對改寫，一次改寫走四個階段；新的 active pair 要等接好線才能取用；沒事做的 tile 向鄰居拿一對，拿到的下一個 cycle 才能做。
    • 
      
  • 最影響結果的是「一次 interaction 要幾個 cycle」，這一頁設成四個。實際硬體如果比較短，右邊所有的線都會往下移，輸的幾個測試差距會縮小。「加 tile 沒有幫助」「要從頭走」「要複製」「要丟棄」這些性質不會因此改變。
    • 
      
  • 兩邊各照自己最自然的寫法：左邊用 array 和迴圈，右邊用 list、tree 和遞迴。
    • 
      
  • 沒有算能量、面積、clock frequency，也沒有算 tile 之間搬資料的延遲。右邊的 tile 是這一頁自己的簡化版本，和 Frostbite 的設計不完全相同。
