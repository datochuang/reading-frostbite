計算模型是什麼

這一頁沒有程式碼。題目是一張電阻網路，要求 A、B 兩端的等效電阻。同一題會做三次，每次換一套做事的規矩。前兩次直接從電路出發；第三次要先把電路改寫成另一種樣子，頁面會交代這一步是誰做的。規矩之間差在三件事：要算的東西記在哪裡、一步做多少事、下一步由誰決定。這三件事合起來，就叫計算模型。

介紹 interaction net 的文章（包括這個系列另外兩頁）多半拿一段 C 寫法的程式來對照。C 程式本身已經是把題目寫成 von Neumann 模型之後的樣子，從那裡開始看，interaction net 很容易被看成「換一種方式跑同一段 C」。這一頁改從題目本身開始。

做法一直接改圖你在紙上化簡電路的做法 做法二一張表加一份步驟清單von Neumann 模型。C 程式就是這種寫法 做法三Interaction net圖改寫加上限制：下一步在哪裡不用找，同時做不會撞
題目

求 A、B 兩端的等效電阻

可以用的規則只有兩條：

串聯

兩顆電阻接在同一個中間節點上，這個節點沒有接別的東西。換成一顆，阻值是 R₁ + R₂。

並聯

兩顆電阻接在同樣的兩個節點之間。換成一顆，阻值是 R₁R₂ ÷ (R₁ + R₂)。

    做法二

    一張表，加一份步驟清單

    同一張電路，同樣兩條規則。這次電路記成一張表（就是 netlist），由一個執行者照步驟清單一個步驟一個步驟做，一次只看表裡的一兩列。這是 von Neumann 模型：表是 memory，步驟清單是 program，「現在做到第幾個步驟」是 PC。

      一步是什麼
      照清單上目前那個步驟做一個小動作：讀一列、比一下、改一列。同一題總共走了 步，讀表 次，寫表 次。

      清單。做完這個步驟接著做哪一個，清單上寫定了。任何時刻只有一個地方在動。

      清單裡有許多題目沒有要求的決定：表怎麼排、從哪一列開始找、找不到換哪一列、改完從哪裡重新開始。寫 C 或 Python 時做的就是這些決定。這份清單寫得很直白，換一種資料結構可以少讀很多次；不管怎麼寫，「誰和誰相鄰」都要靠讀表才知道。

      所以一段 C 程式不適合當入口。它是做法二的步驟清單，題目已經被寫成「表加順序」了。1977 年 John Backus 的 Turing Award 演講談的就是這件事：主流程式語言是照 von Neumann 機器的樣子設計的，變數對應 memory 的格子，assignment 一次改一格，用這些語言想問題，想到的自然是做法二。

      名詞

      這兩種做法各是一個計算模型

      計算模型是一套規矩，回答三個問題：

      1. 狀態：要算的東西長什麼樣、記在哪裡。
      2. 一步：一次允許做的最小動作。
      3. 下一步由誰決定。

      模型可以一層疊一層。CPU 本身是一塊同步數位電路，這塊電路執行的是 von Neumann 模型；CPU 上的 runtime 再去執行 interaction net，就是三層。

      教科書裡的 Turing machine 和 λ-calculus 也是計算模型。Interaction net 是 Yves Lafont 在 1990 年提出的，屬於圖改寫這一類，多了幾條限制。下一段說明為什麼要加限制。

      為什麼要加限制

      把做法一交給機器，會遇到兩個問題

      1. 要找。每做一步之前，都要先找出圖上哪裡符合規則。人用眼睛掃，機器要去查，圖越大查得越久。
      2. 會撞。兩個可以化簡的地方可能共用同一顆電阻。下面是做法一做完第一回合的樣子：兩個框都要用中間那顆 2 Ω。點其中一個框，看另一個框怎麼了。

      一個人做沒有問題。兩個執行者同時各做一組，就會有一個人改到一顆已經不在的電阻。要同時做，得先協調誰做哪一組，執行者越多，協調越花時間。

      Lafont 的做法是把規矩訂嚴，讓這兩個問題不會出現：

      • 圖上的每個元件叫 node。每個 node 有一個 port 叫 principal port（下圖的尖端），其餘的 port 叫 auxiliary port。Port 之間的連線叫 wire。用 netlist 的話來說，node 相當於一個 instance，port 相當於 pin，wire 是只接兩個 pin 的 net。這裡的 node 和電路的節點 n1、n2 是兩回事。
      • 只有兩個 node 用 principal port 相接時才可以改寫。這一對叫 active pair。Principal port 接到對方的 auxiliary port 時不能動，要等對方先被改寫成別的東西。
      • 每一種 pair 最多一條規則。改寫只換掉這兩個 node；它們的鄰居不變，只是 wire 改接到新的 node 上。
      • 一條 wire 只接兩個 port，沒有 fan-out。同一個值要給兩個地方用，得放一個專門做複製的 node。

      上面第二張圖是沒有 fan-out 的後果。在電路裡一條線分岔就好；在這裡要放一個複製的 node（習慣寫成 δ）。它遇到一個數字，一步抄成兩份。遇到的如果是一大塊資料，它要一個 node 一個 node 抄下去，抄多少就花多少步。用不到的資料也要靠另一種 node 一個一個清掉。

      不用找
      Active pair 是在兩個 principal port 被接上的那一刻出現的。做改寫的執行者當場就知道，把它記進一張待辦清單就好，不用回頭掃整張圖。這裡省掉的是「下一步在哪裡」的搜尋。題目本身的結構（誰串誰並）不會因為換模型就消失，下一段會看到它由誰處理。
      不會撞
      一個 node 只有一個 principal port，所以最多屬於一個 active pair。任何兩個 active pair 都沒有共用的 node，可以同時改寫。
      順序無關
      不管先做哪一對，最後的圖一樣，總共做的次數也一樣。做法一也有這個性質，但那是串聯、並聯這兩條規則剛好有的；interaction net 是任何一組規則都保證。
      代價
      一個 node 一次只能在一個 port 上反應。有兩個輸入的運算要拆成兩步：先遇到第一個輸入，再遇到第二個。沒有 fan-out：資料要用兩次得複製，用不到得丟棄，這兩件事都要算步數（對照頁第 8 章有完整的例子）。
      做法三

      同一題，改寫成 interaction net

      電路圖不能直接當 interaction net 用。一顆電阻有兩端，兩端地位相同，沒有哪一端可以當 principal port。每個計算模型都要先把題目寫成它看得懂的樣子：做法二寫成一張表加一份步驟清單；這裡要寫成一張由 node 組成的圖，加一張規則表。

      寫法是先把電路的結構寫成一條式子：((2 + 3//6) + 4) // (5 + 3)，＋ 是串聯，// 是並聯。哪幾顆串、哪幾顆並，是寫的人先看出來的。實務上這是寫程式的人和 compiler 的工作。做法二的 步大部分就是在找這件事，所以下面的步數不能和 步比。要比的話，同一條式子交給 von Neumann 模型是 個步驟：算 3//6 記在 t1、算 2 + t1 記在 t2、算 t2 + 4 記在 t3、算 5 + 3 記在 t4、算 t3 // t4。

      軟體實作和硬體實作

      右邊那張表就是「軟體實作」。把這張圖交給一般 CPU 執行時，每個 node 是 memory 裡的一列。Runtime 是一份步驟清單：從待辦清單拿一對，讀這兩列，照規則寫入新的列，再把鄰居的欄位改接過去。這是做法二的機器在執行做法三的模型。HVM 這類 runtime 都是這樣跑的，1990 年到現在的 interaction net 幾乎都是這樣跑的。這一題下來讀 列、寫 列。

      硬體實作是把 runtime 那份步驟清單做成電路：待辦清單變成 queue，規則表變成查表的邏輯，node 放在晶片上的 memory 裡。這樣一份單元叫一個 tile，很多個 tile 同時各做各的 active pair。設計者的主張是：tile 只做這一件事，可以省掉通用 CPU 為了執行任意 instruction 而帶著的許多機制。要另外付的成本在 tile 之間：一對 active pair 的兩個 node 落在不同 tile 時，得先透過 tile 之間的網路送到同一處。它實際上快多少，目前只有 Frostbite 自己公布的 pre-silicon 數字，沒有晶片實測。對照頁第 2 章畫的是一個 tile，第 9 章是多個 tile 分工。

      「不會撞」是模型層次的保證：兩個 active pair 沒有共用的 node。實作上相鄰的兩對會共用一條 wire，兩邊同時改接時還是要處理。HVM 的做法是把 wire 做成 atomic 的變數，不用 lock。這是 runtime 與硬體設計裡花工夫的地方。

      把數字直接放進 node 是實作上的擴充，HVM 就是這樣做的。1990 年的原始定義裡 node 只有符號，數字要用一串 node 來表示。實務上也不會有人手畫這張圖：先用高階語言寫（例如 Bend、Vine），再由 compiler 轉成 net，就像 C 由 compiler 轉成 instruction。

      程式在哪裡。在 interaction net 裡，一個程式是一張規則表加上一張起始的圖。規則表有兩種定法。這一頁用的是每個程式自己定規則：＋、//、「梯」都是這個程式定的 node。HVM 用的是另一種：規則固定成少數幾條通用的（叫 interaction combinators，再加上數字運算）。這時「梯」不再是一條規則，compiler 會把它轉成一小塊用通用 node 拼成的圖，放進起始的圖裡。Frostbite 公布的設計也是固定的幾類 node；規則固定，硬體的規則表才定得下來。

      為什麼做得到。Node 是 memory 裡的一筆資料，可以隨時多一筆、少一筆。Gate 是矽上的東西，數目在 tape-out 時就定了，所以一塊固定的 combinational datapath 做不到這件事。CPU 做得到，是因為會變大的東西放在 memory 裡。Interaction net 也一樣，執行它的東西一定要有一塊可以隨時配置、釋放 node 的 memory：軟體 runtime 用 heap，Frostbite 的設計是每個 tile 自己有一塊 node memory。Interaction net 和 von Neumann 一樣是通用的計算模型，這一點有數學證明（它和 Turing machine 等價）。這一頁只示範了其中一個必要條件：圖要能長大。

      並排

      同一題，幾種做法

      做法從什麼開始一步做的事總步數能不能同時做要另外付出的
      一　直接改圖電路圖相鄰的兩顆換成一顆 次不重疊的可以， 回合每一步都要先找哪裡能化簡；同時做要協調重疊
      二　表加步驟清單netlist讀一列、比一下、改一列 步模型本身一次一步大部分的步數花在讀表，找誰和誰相鄰
      同樣是 von Neumann式子算一個運算，結果記一格 步模型本身一次一步式子要有人先寫好；順序和暫存的格子是寫的人定的
      三　Interaction net式子一個 active pair 換成規則指定的 node 次清單上的全部可以， 回合式子要有人先寫好；每一步都要配置、釋放 node，改接 wire

      各列步數的單位不同，一步的大小不一樣，不能直接拿來比快慢。能比的是最後兩列，兩邊都從同一條式子開始：von Neumann 步，interaction net 次改寫、 回合。這一題太小，interaction net 沒有佔到便宜。每個運算拆成兩步是固定的代價，同時做的好處要等題目變大才追得回來。表裡的「一次一步」說的是 von Neumann 模型本身；實際的 CPU 會用 out-of-order、SIMD、多核去同時做，靠的是硬體或 compiler 另外找出哪些步驟互不相干。

      題目放大之後

      把電路換成一棵平衡的串並聯結構：兩顆合成一組，兩組再合成一組，一路合到只剩一顆。下表是這一頁的小程式實際跑出來的數字。

      電阻顆數一個執行者照式子算（von Neumann）：幾步Interaction net：改寫幾次Interaction net：幾回合

      一個執行者照式子一步一步算，步數跟著顆數走；interaction net 的回合數跟著層數走。這棵樹交給多個 thread 或一棵 adder tree，也能跟著層數走，差別在於那需要人或 compiler 先看出哪些部分互不相干。Interaction net 是模型的規矩本身就保證，不用另外分析。2005 年前後多核心 CPU 普及之後，相信這個模型有用的人主要看上的就是這一點。回合數有一個前提：每一回合有夠多的執行者，把清單上的 active pair 一次做完。執行者只有 P 個時，一回合最多做 P 對。另外，每一次改寫在 CPU 上要讀寫好幾列，比 von Neumann 的一步大。軟體 runtime 目前量到的是單一 thread 比一般 compiler 產生的程式慢 3 到 17 倍（多半是各專案自己報的數字）；專用硬體能不能把這個差距收回來，還沒有實測。
